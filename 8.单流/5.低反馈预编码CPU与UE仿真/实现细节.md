# UPA CPU链路实现细节

## 1. 信息边界与数据维度

设当前有B台协作AP，每台32×32天线，UE为4天线。第b台AP信道`H_b`为4×1024，按**活动物理AP顺序**横向拼接为`H=[H_b1,...,H_bB]`，大小4×1024B。预编码为1024B×1，只发一条数据流。

代码把环境真值和公共网络配置分开：

```matlab
[net,sim,bank] = upa.load_inputs;
sample = upa.sample_channels(net,sim,bank,sample_id); % 环境／评估器
[Htrue,Hobs] = upa.observe(sample,channel,active_ids,obs_snr);
messages = upa.encode_directions(net,Hobs,active_ids,refs,14); % UE
design = upa.cpu_from_message(net,messages.DFT,active_ids);   % CPU
```

CPU入口只接收固定的`net`、参考AP方向整数消息和公共活动ID；不接收`bank`、`sample`、Hobs、Htrue或真实UE位置。消息字段只有`method`、`reference_ap_ids`、`integer_codes`、`q_frequency`，附加真值字段会直接报错。AP集合、算法类型、量化配置作为双方预配置，不重复计算静态标识开销。

CPU输出包含估计位置、各AP最终DFT索引、连续共相位、完整预编码及反馈比特计数。评估器之后才用真值计算误差和接收性能。

## 2. 物理坐标与真实信道

载频7 GHz，`lambda=3e8/7e9`，阵元间距`d=lambda/2`。AP局部UPA放在yz平面：

`a_local(ny,nz)=[0,(ny−15.5)d,(nz−15.5)d]^T`，`ny,nz=0,...,31`。

物理坐标为`a_AP=b_AP+R_AP*a_local`。采用JSON中的完整局部到全局旋转矩阵R。MATLAB列优先存储中ny变化最快；全部reshape、FFT和码字均沿用这一顺序。

UE第u根天线坐标为`p_UE+[(u−2.5)d,0,0]^T`，u=1,...,4。真实LoS信道按逐阵元精确距离生成：

`r_un=||a_AP,n−a_UE,u||`，`H_LOS(u,n)=exp(−j*k*r_un)/r_un`。

因此真实信道保留单AP内部波前曲率和多AP路径差。CPU后续采用局部平面波模型；两者不是同一信道生成器。

混合信道按冻结的六个散射点生成。每个样本的六个复系数ζ在全部AP、方法、SNR、B之间共享。单次反射总路径长度为`L_unl=||a_AP,n−s_l||+||s_l−a_UE,u||`，原始散射矩阵：

`A_b(u,n)=sum_l ζ_l exp(−j*k*L_unl)/L_unl`。

先令`A_scaled=A_b*||H_LOS,b||F/||A_b||F`，再生成

`H_mix,b=sqrt(K/(K+1))*H_LOS,b+sqrt(1/(K+1))*A_scaled`，K=10。

最终混合H不再归一化。该模型是已约定的LoS主导六径模型，不是纯NLoS或完整3GPP信道。

## 3. 观测SNR与数据工作点

每个物理AP按共享种子生成标准复噪声`Z_b=(N1+j*N2)/sqrt(2)`，随机流为MATLAB twister。相同样本和物理AP的Z在所有方法、信道、B和观测SNR复用。改变B时，只重算当前活动H的**全局**噪声方差：

`sigma2=mean(abs(Htrue_active(:)).^2)/10^(obs_snr/10)`，`Hobs=Htrue+sqrt(sigma2)*Z_active`。

不能按每AP分别归一化，也不能每个方法重新抽噪声。噪声缩放是仿真观测模型，不将Htrue作为CPU输入。

数据链路使用固定`rho=10/Sref`，`Sref=0.25445623637403425`。参考数据SNR 10 dB与横轴20–40 dB观测SNR含义不同。Sref不随UPA天线数、B、UE位置或方法重新计算。

## 4. UE方向消息

### 4.1 DFT方向

参考AP从自身带噪子信道`Hobs_b`求主右奇异向量v_local。搜索最终发射码本：

`f(my,mz)[ny,nz]=exp(j*2*pi*(ny*my+nz*mz)/128)/32`。

每维128个索引，每AP共128²=16384个码字。指数使用未中心化序号ny,nz，而阵元物理坐标已中心化。不能自行改变其中一个约定，否则AP间共相位会错位。

利用`fft2(reshape(v_local,32,32),128,128)/32`同时得到所有`f^H*v_local`。选择最大相关幅度，平局取线性索引最小者。反馈两个7 bit整数my、mz，也可展平为`mflat=my+128*mz`。本版CSV存二维整数，计费仍为14 bit/AP。

### 4.2 HAQSE方向

每参考AP直接使用4根UE天线的带噪CSI：

```matlab
f = MMV_CF_mQSE2_SumOfRatios( ...
    reshape(Hobs_b.',[32,32,4]),1,1,1,3);
```

这里必须使用普通转置`.'`，不能使用共轭转置`'`。第三维为4个观测快拍；没有传入真实角度或真实LoS标签。函数原文件保存在lib中，未更改估计逻辑。

输出空间频率`nu_y,nu_z`先wrap到[−0.5,0.5)。定义q为UE指向AP的单位向量，则局部`nu_y=−q_y/2`、`nu_z=−q_z/2`。

每维q_f=14 bit，L=2^14，沿用UPA同步协议的**端点量化**：

`k=clip(round((nu+0.5)*(L−1)),0,L−1)`，CPU解码`nu_hat=−0.5+k/(L−1)`。

不要替换为ULA曾使用的圆周量化规则。本接口只反馈两个整数k，不反馈浮点频率或观测信道。

## 5. CPU定位与全部AP波束推断

DFT消息先逐维解码：`nu_hat=−wrap(m/128)`。HAQSE消息按上一节解码。

令`y=−2nu_y`、`z=−2nu_z`，选择部署已知的阵列前半空间：

`q_local=[−sqrt(max(0,1−y²−z²)),y,z]^T`。

若量化／估计使y²+z²>1，将上述向量单位化，并记录越界次数；不偷偷恢复真实角度。AP指向用户的全局射线为`g=−R_AP*q_local`。

对所有参考AP构建`P_b=I−g_b*g_b^T`，非加权射线最小二乘解为：

`p_hat=(sum_b P_b) \ (sum_b P_b*p_AP,b)`。

不把p_hat裁剪回20–30 m活动区；越出区域仍保留样本，记录状态。若方程奇异或数值非有限则直接停止并报错，不删除不利样本。

有p_hat后，对每个活动AP计算局部几何方向q_local，并映射到128×128发射码本：`m=mod(round(128*q_local(y,z)/2),128)`。

参考AP有两个重要例外：

- DFT参考AP直接保留UE反馈的原始索引，不用定位后重新选束。
- HAQSE参考AP用自身已反馈的频率映射发射索引`mod(round(−128*nu_hat),128)`。

只有未反馈AP完全依靠估计位置推断方向。这样能够把“少反馈AP的方向”与“所有AP最终都要发射”联系起来，同时避免位置拟合反过来改坏已有参考波束。

## 6. CPU共相位与预编码

对每个AP，设`r=||p_AP−p_hat||`，`q=(p_AP−p_hat)/r`，`q_local=R_AP^T*q`。CPU构造局部平面波信道：

`Hmodel_b(u,n)=exp(−j*k*r)/r * exp(+j*k*delta_UE,u^T*q) * exp(−j*k*q_local^T*a_local,n)`。

中心距离r对应的传播相位必须保留。该模型没有恢复真实散射分量、设备相位偏差或实际信道残差。

拼接Hmodel后取主右奇异向量v_model。代码利用4×4矩阵`Hmodel*Hmodel^H`求最大特征对，再计算`v_model=Hmodel^H*u/sqrt(sigma1²)`，避免对4×1024B矩阵进行大型完整SVD。

对每个**实际发射波束**f_b，取`a_b=f_b^H*v_model,b`。计算

`c_b=exp(j*(angle(a_b)−angle(a_1)))`，`w_b=c_b*f_b/sqrt(B)`。

最终`||w||²=1`，每AP功率1/B。c是CPU内部连续计算值，不计UE相位反馈。虽然几何模型显式依赖毫米级路径差，模型精确计算本身不能消除方向量化与定位误差。

## 7. 三条共同基线

Ideal SVD使用真实H的主右奇异向量，总功率1，允许AP间不等幅度；它是上界，不计反馈bit。

Type-I使用联合带噪Hobs的主右奇异向量v_obs，每AP选择一个最大相关DFT波束。UE对该实际波束取`f_b^H*v_obs,b`，相对AP1均匀量化为4 bit。CPU按反馈索引、相位组装等AP功率预编码。

Type-II沿用双方v2约定的简化两束实现：

1. 将4倍过采样DFT分为16个正交组；每组my=oy+4ky、mz=oz+4kz，oy、oz为0–3，ky、kz为0–31。
2. 各组按相关能量选择最强两束，取二者能量和最大的组；强束在前。
3. 令弱束／强束幅度比为r，3 bit量化到0、1/7、...、1；相对相位用2 bit圆周量化。
4. 用`f_strong+r_hat*exp(j*delta_hat)*f_weak`合成并归一化为单位范数。
5. UE重新针对合成后的实际波束计算AP间共相位，统一4 bit；最后仍是每AP功率1/B。

Type-I／II都使用Hobs，而不是理想H；在CPU性能面板内也不改为模型相位。Type-II为项目简化基线，不是完整3GPP码本。

## 8. 反馈计费

|方法|CPU链路每次更新bit|B=8|
|---|---:|---:|
|DFT R=3|3×14|42|
|DFT R=5|5×14|70|
|HAQSE R=3|3×2×14|84|
|HAQSE R=5|5×2×14|140|
|Type-I|B×14+(B−1)×4|140|
|Type-II|B×(2×14+3+2)+(B−1)×4|292|

仅计UE上行更新字段，不含协议头、CRC、静态集合ID、CQI／RI、训练和CPU向AP下发。不能将CPU算出来的c_b误算成UE反馈，也不能省略基线的内部两束系数。HAQSE R=5在B=8时与Type-I同为140 bit，不宣称它有反馈节省。

## 9. 评估公式与相位RMSE

对真实H和最终w，计算`P=||H*w||²`，`G=P/sigma1(H)²`。单样本G应位于[0,1]。

- 主报告BF增益：`sqrt(mean(G))`；CSV同时保留`mean(G)`，避免开平方口径混淆。
- 平均频谱效率：`mean(log2(1+rho*P))`，单位bit/s/Hz。
- 平均吞吐量：20×平均频谱效率，单位Mbps；不能先平均P再取对数。
- 位置RMSE：`sqrt(mean(||p_hat−p_true||²))`，单位m。

相位目标使用真实H的主左奇异向量u_true，针对每种方法**各自实际波束**定义`a_true,b=f_b^H*H_b^H*u_true`。比较设计c_b与a_true,b相位，均按2π环绕到[−π,π]。

同时统计：

1. AP1相对相位RMSE：b=2,...,B的相位差误差。
2. 全AP对相位RMSE：所有i<j的两两相位差误差。

主相位诊断优先看全AP对口径，避免只看AP1的特殊几何。逐样本保存误差平方和与有效比较数，汇总时先求总平方和／总计数再开方。目标投影近乎零、幅度小于本样本最大投影的1e−10时，其相位不稳定，因此只在相位统计中排除对应比较，并显式保留有效计数；通信性能样本不会因此删除。

接收功率采用理想单流接收合并`||H*w||²`。这是共同评价假设，不表示发射端或CPU具有完美CSI。

## 11. UE端相位反馈分支

入口`run_upa_ue('Mode','full')`与CPU分支使用同一位置、信道、噪声、SNR和7种方法，只有低反馈链路的共相位来源不同。UE已经从部分参考AP方向消息得到与CPU相同的估计位置，并能复现共同的方向解码规则，所以能本地生成与CPU一致的全部活动AP发射波束。方向消息中的DFT索引保持不变，HAQSE频率按同一端点规则解码；非参考AP根据估计位置选择DFT码字。

UE以真实可观测的带噪全网CSI求联合主右奇异向量`v_obs`，逐个实际波束计算`a_b=f_b^H*v_obs,b`，然后对相对AP1相位均匀量化为Q=4 bit。发送给CPU的字段为`[k_2,...,k_B]`，k1固定为0，无需传公共相位。CPU把收到的相位整数解码成`c_b=exp(j*2*pi*k_b/16)`，最终使用`w_b=c_b*f_b/sqrt(B)`。

此分支不会把完整带噪信道交给CPU；UE只增加`4(B−1)`个相位bit。方向加相位总开销为：R3 DFT=`42+4(B−1)`，R3 HAQSE=`84+4(B−1)`，R5 DFT=`70+4(B−1)`，R5 HAQSE=`140+4(B−1)`。例如B=8分别为70、112、98、168 bit。HAQSE R5在B=8的总开销高于Type-I的140 bit，因此需按图中实际性能和开销一起比较。

UE分支自动输出四幅均值图：`E1_UE_throughput_SNR.png`、`E2_UE_throughput_AP.png`、`E1_UE_BF_gain_SNR.png`、`E3_UE_feedback_AP.png`，并各有可编辑FIG文件。图中两种信道各占一个子图，400位置取均值，无置信区间阴影。前三幅含共享SVD／Type-I／Type-II基线，反馈图使用UE总bit列。

## 10. 完整运行与核查方法

E1有5个SNR点，E2有6个B点，B=8／30 dB重合一次，共10个唯一设置。两类信道×7种方法得到140个case；400样本对应56000条逐样本记录。

运行时检查预编码范数、等AP功率、G≤1、case唯一性，以及每条case的预算与冻结运行清单一致。CPU低反馈曲线的`phase_source=CPU_model`，Type-I／II为`UE_estCSI`，SVD为`ideal_truth`。

与另一端对齐时，推荐先核对`debug_sample1_LOS.mat`中的方向消息与最终发射索引，再核对相对AP1的c。不要直接比较未消除整体相位的奇异向量，不要将物理AP编号当成H矩阵中连续块编号。

`shared/source_hashes.json`记录原始输入和HAQSE函数的SHA256；交付核查报告另见根目录`delivery_audit.json`。主入口没有访问原同步目录之外的隐式依赖，整个文件夹可复制给协作者直接运行。
